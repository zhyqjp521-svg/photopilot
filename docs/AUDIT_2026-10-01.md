### 1. 异常恢复保护

复现：旧项目含缺失／变化原图或损坏 JSON；开始部分成功、取消、跳过文件或失败的新扫描；或交错两次恢复请求，先发请求后返回。

预期：仅最新恢复请求可改变保护状态；只有完整、无错误的新扫描才能解除保护。开发中测试发现旧请求或部分扫描能错误改变状态。修补后以独立 request/generation 标记拒绝旧响应，并传播上传缺失和扫描不完整标记。新扫描未获得可用照片前保留旧图库；异常项目禁止覆盖旧存档。

验证：前端缺失／损坏、部分扫描、跳过、取消、重叠恢复和 INIT_FOLDER 回归全部通过。实际浏览器移走自有一张原图，页面显示两张可用照片，操作后旧 checkpoint 哈希不变；损坏 JSON、重试及空失败扫描同样通过。

证据：[缺失保护](qa-2026-10-01/missing-original.png)、[损坏存档提示](qa-2026-10-01/corrupt-checkpoint.png)。

### 2. 启动无害操作丢弃恢复

复现：延迟真实 GET `/api/project` 响应，在返回前按 Tab 并点击保存。

预期：导航／保存请求不能被识别为替换图库的意图。修补前真实浏览器超时，状态停留在等待保存，三张旧照片未恢复。修补后只记录真实控件改变和明确按钮修改的意图，无害点击不阻止恢复。

验证：Tab、body click、保存三项行为回归及真实浏览器重放均通过；密度按钮等真实更改仍能保护新值。

证据：[恢复成功](qa-2026-10-01/startup-keyboard.png)。

### 3. 手势历史被自动保存拆分

复现：持续拖动一个调色滑杆，在中间触发项目 snapshot，再继续拖动到最终值。

预期：存档捕获最新值，但一次完整拖动仍只有一步撤销。修补采用保留活动手势的 flush，最终输入更新同一历史项；回到起点是 noop，不清除原有 redo。

验证：持续手势、键盘连按、重置撤销、50 状态上限、redo 分支截断和保存中的手势回归通过。实际浏览器完成调节、重置、撤销／重做和快捷键操作。

证据：[单张编辑器](qa-2026-10-01/editor.png)。

### 4. 导出参数冻结遗漏

复现：开始导出后调用全局重置，或令先前开始读取的参数 JSON 在导出期间读取完成。

预期：显示值、捕获参数和输出设置保持一致。审核发现全局 toneActions／recipeFile 漏锁。现导出时统一锁定相关控件，重置和异步文件读取有运行时保护，结束或关闭后恢复各控件原来的 disabled 状态。

验证：五项新增行为回归先失败后通过；真实浏览器检查导出期间相关控件均禁用。

### 5. 迟到预览抹掉导出结果

复现：延迟真实预览响应，在它返回前完成导出，然后释放旧预览。

预期：仍显示已导出尺寸和下载链接。现以 editor 身份、revision 和 renderEpoch 拦截旧成功／错误返回。没有新调节时不会自动再刷新预览。

验证：真实浏览器导出成功后释放旧响应，状态和链接不变；旧成功／失败行为回归均通过。

证据：[导出与预览竞态](qa-2026-10-01/export-preview-race.png)。

### 6. 导出后最新调节预览漏掉

复现：旧预览响应被延迟 → 导出完成 → 再调节曝光 → 等待 350ms debounce 在 busy 状态触发 → 释放旧预览。

预期：渲染新的曝光值。修补前真实浏览器等待超时，页面仍停留在已导出状态；调色值已经变化但没有新预览。现用 previewPending 明确保存未处理的预览意图；旧请求 finally 释放 busy 后处理最新输入，不再以旧 epoch 阻止调度。

验证：新增行为测试 RED → GREEN；真实 Chrome 重放通过，最后请求曝光等于滑杆最新值，页面显示「预览已更新」。旧请求成功和失败路径也经独立探针验证。

证据：[再次调节已更新](qa-2026-10-01/preview-after-export.png)。

### 7. 缺失警告布局

复现：恢复含大量长路径的缺失清单。

预期：恢复／保存按钮可见，不被警告顶出可用画布。现限制样本数量、单路径长度和 96px 警告滚动高度，使用 textContent；浅／深色警告颜色对比经检查约为 6.3／12.0。

验证：独立浏览器大清单布局检查通过；最终源码 1000×720 深色、减少动态效果模式下保存按钮可见、图库可用，无 pageerror。Impeccable 检查最终源码返回 `[]`，不等同于完整辅助技术认证。

证据：[紧凑深色布局](qa-2026-10-01/compact-dark.png)。

## 边界及后续

- 仅最近一个项目。显式保存等服务器确认；关闭事件尽力保存，不保证强制退出前最后一瞬间的操作。没有多窗口／多浏览器协作合并协议。
- 存档引用原图路径，不备份原图。新的扫描／导入替换图库并清理草稿；继续上一批应恢复项目而不是重新扫描。中断扫描只恢复清单，不恢复线程。
- 历史仅包含曝光、对比度、高光、阴影、冷暖、饱和度，每照片一个兼容处理基底、最多 50 状态；不是磨皮／修脸／笔刷的完整非破坏编辑栈。
- JSON 有 16MB、20,000 张照片及深度／节点等上限；写全量 manifest，不宣称超大图库增量性能。本轮没有新增速度倍数基准。
- 未实测最新 WKWebView、重新安装／图标、相机 RAW 大批量、真实婚礼人脸质量和所有屏幕阅读器操作。旧综合套件的静态 UI 断言不是实际桌面验收。
  后续已补做 WKWebView 的基础导入／调节／导出／重启恢复；其他未覆盖项仍然成立。
- 本轮无新增模型、下载 LUT 或第三方预设。旧 NIMA 权重仍停用；商业分发继续依据 `docs/COMMERCIAL_USE.md` 做完整依赖／资产审计，不作全产品法律保证。
- 下一阶段可做持久导出队列、失败重试与任务恢复，然后再扩展完整精修栈；本轮没有实现这些阶段。
