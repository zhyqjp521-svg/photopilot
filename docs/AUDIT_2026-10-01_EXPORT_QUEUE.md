## 基线与边界

本轮修改前，51 项 Python 测试和 57 项前端行为回归通过。已有未提交修改保留，本轮没有提交或推送代码。实际验收只使用自行生成的 PNG，不使用或修改用户原始照片。

退出应用不等于后台服务继续运行。窗口重新加载时引擎仍可工作；应用重启时未完成任务需要明确继续。暂停在当前照片结束后生效。仅清除任务记录不会删除成品。

- 队列、配方、读取性能增量、服务端、界面均完成独立规格与质量审核；静态新增代码扫描无硬编码凭据、shell 注入、eval/exec、pickle 或拼接 SQL 模式。最终独立集成审核通过，并独立复跑 Python 137 项及前端 79 项。
- 真实浏览器：自行生成的 3 张 1800×1200 PNG，窗口重载没有新任务；暂停后引擎在下一项 running 检查点中断，重启恢复为 paused，明确继续后成功 3 / 失败 0。原图及先前成功成品 SHA-256 不变。
- 失败重试：临时移动一个待处理源图（仅测试副本），得到成功 2 / 失败 1；原路径及原文件恢复后，改变当前曝光和磨皮参数再点「重试失败项」，同一任务成功 3 / 失败 0，成功项哈希不变；重试成品哈希与冻结配方独立渲染基准一致。
- 结果采用 640px 缩略图；实际点击完整成品下载，下载哈希与磁盘完整输出一致。单张仍打开大图编辑，不产生批量任务；1440×920 下实测画布 1094×743。
- 1440、1024、768 宽度下队列本身无横向溢出，按钮保持横排；这不代表整个桌面软件已做完手机适配。上述真实浏览器流程均无页面 JavaScript 异常。
- 已安装原生 APP：唯一 PhotoPilot 主窗口，实际设置测试目录、扫描 3 张、全选、美化批量导出、打开结果。队列成功 3 / 失败 0，原图 SHA-256 与测试输入一致。操作通过后台 AX 进行，未抢占用户前台程序。

## 已知设计限制

队列最多保留 20 个任务，每任务最多 20,000 张，冻结配方上限 16 MB，总状态上限 64 MB。完成／失败任务可明确移除记录腾出空间。原图没有随队列备份，丢失或变化会阻止相应项目导出。进程在发布成品后、记录完成前中断时，恢复会报告已有文件冲突，不覆盖该文件。

测试过程记录：一个子任务误运行未隔离的历史 `tests/run_all.py`，根代理发现后停止了该精确测试进程。它重写了项目 `demo` 下的测试用流水线成品、XMP 和白平衡成品；没有删除文件或触及用户原始照片，保留现场。后续历史套件改在完整临时副本运行。

原子 JSON 快照每次状态迁移重写全部记录，含冻结参考像素；这是有上限的桌面实现，不是无限历史或超大交付数据库。后续可迁移到事务存储。本轮不增加第三方预设、模型或素材，也不是全产品零 bug／竞品功能对等证明。

本轮验证正常进程中断／重启和模拟存储失败，不提供硬件断电、介质故障下的持久性保证。实际照片操作测试为 macOS 与隔离 Chrome，未做本轮 Windows/Linux 原生窗口或大批真实相机 RAW 验收。

合成开销测量（不是导出吞吐基准）：2,000 项、4 MiB 模拟冻结参考、4,586,293 字节快照。五次状态保存开启 tracemalloc 的中位耗时 0.288 秒，Python 分配峰值约 26.3 MB；另一次 cProfile 记录 0.192 秒，主要在 JSON 编解码及 deepcopy。该测量定位了大任务快照成本，不能据此宣称万张级导出性能通过验收。脚本与所有数据位于隔离临时目录，无实际图像渲染或用户文件操作。

只读路径的 20,000 条目合成比较（7 次中位数）：摘要读取从 192.226 ms 降至 4.888 ms；50 条分页从 182.232 ms 降至 5.231 ms。新增 deepcopy 陷阱回归与独立审核确认未请求条目、冻结参考像素不被复制。统计仍在锁内扫描全量条目，这不是常量时间查询，也不是图像导出吞吐测量。
